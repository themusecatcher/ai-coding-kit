# docs 表格规范（列名 / 列数 / 必填标记 / 标题命名）

> 本文件是「组件文档与工具函数文档中所有表格」的**单一权威规范源**。阶段 4（文档）写表时按需加载，阶段 5 由脚本 `B9` 校验。
> 2026-10-23 制定。背景：全量盘点 73 个组件文档 346 张表格后发现——`## Slots` / `## Events` 已 100% 统一，但 `## APIs` 下第一列「参数 / 名称」5:5 分裂（Props 表 84 张用「参数」、Type 表 65 张用「名称」），Type 表存在 4 种形态，39 处类型标题与属性表引用的公开名不一致（`TabsItem` → `### Item Type`，占 87 个类型标题的 45%），且「自定义样式 / CSS 变量」等边缘表格完全无规范。本文件逐项定死。
>
> **与项目权威源的关系**：项目内 `development/demo-doc-guide.md` 是贡献者向权威源，本文件是其 docs 表格部分的**细化实现 + 决策记录**。两者必须同源，改动一处立即回填另一处（见 SKILL.md §项目规范权威源）。

## 0. 三条第一性原理

| 原则 | 含义 | 反例 |
|:--|:--|:--|
| **列名全站唯一** | 同一语义的列在任何表里叫同一个名字，读者不需要在词表间切换 | 同一份文档里 Props 表叫「参数」、Type 表叫「名称」 |
| **结构决定列数** | 列的取舍由「该类型有没有这个维度」决定，不为了美观强行四列 | 给类型别名（`MenuKey = string \| number`）套 4 列 → 「说明」「默认值」两列恒空 |
| **信息只写一次** | 必填信息只在一个位置表达，不重复也不遗漏 | Type 表既写 `key?` 又在默认值列写「必填」 |

### 列名总表（唯一口径）

| 表 | 列名 | 列数 |
|:--|:--|:--|
| 组件 Props 表（`## APIs` → `### {组件名} Props`） | 名称 \| 说明 \| 类型 \| 默认值 | 4 |
| 类型表 · 接口 / 对象结构 | 名称 \| 说明 \| 类型 \| 默认值 | 4 |
| 类型表 · 组件产出的回调 / 实例信息 | 名称 \| 说明 \| 类型 | 3 |
| 类型表 · 类型别名 / 联合 / 枚举 | 名称 \| 值 | 2 |
| 枚举 / 占位符值清单（无名称维度） | 值 \| 说明 | 2 |
| `## Slots` | 名称 \| 说明 \| 用法 | 3 |
| `## Methods` | 名称 \| 说明 \| 类型 | 3 |
| `## Events` | 名称 \| 说明 \| 类型 | 3 |
| 工具函数 `## Params` | 名称 \| 说明 \| 类型 \| 默认值 | 4 |
| 工具函数 `## Return`（纯函数，单返回值） | 类型 \| 说明 | 2 |
| 工具函数 `## Return`（composable，返回对象） | 名称 \| 说明 \| 类型 | 3 |
| `## CSS 变量` | 名称 \| 说明 \| 默认值 | 3 |
| `## 自定义样式`（DOM 类名） | 名称 \| 说明 | 2 |
| format 占位符清单（无名称维度） | 标识 \| 示例 \| 描述 | 3 |
| 键盘操作（无名称维度） | 按键 \| 说明 | 2 |
| 离散 API 调用方式（无名称维度） | 调用方式 \| API \| 适用位置 | 3 |

❌ **禁止出现的列名**：参数、字段、属性名、方法名、事件名、插槽名称、回调参数（历史写法，一律按上表收敛）。

> 标注「无名称维度」的 4 类表（枚举值清单 + format 占位符 + 键盘操作 + 离散 API）是「首列 = 名称」的**显式例外**，首列按各自语义命名；其余任何表首列都必须叫「名称」。

## 1. 组件 Props 表

### 1.1 标题

| 场景 | 标题写法 | 示例 |
|:--|:--|:--|
| 单组件 | `### {组件名} Props` | `### Button Props` |
| 复合组件（主 + 子） | 逐个 `### {子组件名} Props` | `### Descriptions Props` / `### DescriptionsItem Props` |
| 同一文件多个并列组件 | 逐个 `### {组件名} Props` | `### Checkbox Props` / `### CheckboxGroup Props` / `### CheckboxGroupOption Type` |

- 组件名用**注册名（PascalCase）**，与 `types/global-components.d.ts` 一致（`qr-code` → `### QRCode Props`，`grid` → `### Row Props` / `### Col Props`）。
- ` Props` 后缀不可省：它是与 `### {类型名} Type` 的**平行结构**，读者一眼区分「组件属性 / 数据类型」。
- ⚠️ 改标题即改锚点（`#descriptions` → `#descriptions-props`），必须同步页内与跨页链接。脚本 `B9` 校验。

### 1.2 首列「名称」与状态标签

- 固定为**名称**，即使内容是 `v-model` 绑定的 prop。
- 状态用 **`<Tag>` 标签**写在名称后（与 `v-model` 同款表达，位置固定、可扫读）：

| 标签 | 颜色 | 含义 | 写法 |
|:--|:--|:--|:--|
| `v-model` | `cyan` | 双向绑定 | `open <Tag color="cyan">v-model</Tag>` |
| `required` | `red` | 必填（源码 `required: true`，或该 prop 无缺省且组件无法运行） | `value <Tag color="red">required</Tag>` |
| 两者并存 | — | 顺序固定 `v-model` 在前、`required` 在后 | `value <Tag color="cyan">v-model</Tag> <Tag color="red">required</Tag>` |

- **❌ 名称列不写 `?`**：可选是常态（实测 2026-10-23：扫描全库 `export interface Props`，无 `?` 的字段仅内部组件 `popup/Popup.vue` 的 `defaultZIndex` 1 处，对外组件无必填 props），逐行标 `?` 是零信息量噪音；必填用 `required` 标签 + 默认值列 `—` **双标记**（标签给扫读、`—` 给精确语义）。
- 名称与源码 `Props` 字段逐字一致（`inlineCollapsed` 不写成 `inline-collapsed`）。
- ⚠️ `required` 标签只在**真必填**时使用：源码 `required: true` 或该 prop 缺失即无法工作（如 `id`）。可选 prop 即便业务上常用也 ❌ 不加标签，否则标签贬值。

### 1.3 类型列

- 写**真实 TS 类型**，用公开导出名并加链接：`[TabsItem](#tabsitem-type)[]`。
- ❌ 禁 `string | slot` / `Array | slot`（插槽由 `## Slots` 表表达）。
- 联合类型的分隔符写 `&#124;`（HTML 实体），❌ 不写裸 `|`（会被当作单元格分隔）也不写 `\|`（风格不统一）。
- 类型列**不加反引号**（保持纯文本 + 链接，避免表格行高被代码块撑开）；只有出现在**说明列**的类型片段才用反引号。
- 复杂签名写完整：`string | ((record: Record<string, any>, rowIndex: number) => string)`。

### 1.4 默认值列

| 情形 | 写法 | 说明 |
|:--|:--|:--|
| 有明确缺省值 | TS 字面量原样 | `false` / `true` / `0` / `[]` / `{}` / `'large'` / `'top'` |
| 可选但缺省即 undefined | `undefined` | 与源码 `props` 未传时的实际值一致 |
| 必填 / 无缺省 | `—`（em dash） | ❌ 不用 ASCII `-`（与表格分隔线视觉混淆）、❌ 不用「必填」二字 |
| 颜色等语义值 | `'#fff'` 或 `var(--va-xxx)` | 有主题变量时写变量名 |
| 函数 / 对象类型 prop 缺省为空 | `undefined` | 不写 `() => {}` 之类伪默认值 |

必填属真例外场景（如组件的 `value` 确需外部传入）：默认值列写 `—`，必填语义**只由名称列的 `required` 标签表达**（见 §1.2），❌ 不在说明列重复写「必填」（信息只写一次）。

### 1.5 行序

表格行序 **≡ 源码 `Props` 声明顺序 ≡ 六段式分组**（双向绑定 → 内容数据 → 形态外观 → 状态反馈 → 行为交互 → 进阶透传），由 `G2` 校验。禁止按字母序或随手追加。

## 2. 类型章节（`### {类型名} Type`）

### 2.0 位置：紧跟「唯一引用它的表格」

类型表不强制堆在 `## APIs` 末尾，按引用关系就近放置：

| 引用情况 | 位置 | 示例 |
|:--|:--|:--|
| 只被 `## Methods` 的表引用 | 紧跟该表下方（`## Methods` 区块内） | `scrollbar.md` 的 `### ScrollBehavior Type` 紧跟 `### Scrollbar Methods` 表 |
| 只被 `## Events` 的表引用 | 紧跟该表下方 | 事件回调参数类型 |
| 只被 `## Slots` 的表引用 | 紧跟该表下方 | 插槽作用域参数类型 |
| 只被某个组件 Props 表引用 | 该 Props 表所在 `## APIs` 区块内，紧随其后（多个类型表可连续排列成一个类型段） | `### Tabs Props` → `### TabsItem Type` |
| 被多处引用（跨章节 / 跨组件） | 统一下沉到 `## APIs` 区块末尾 | `MenuKey`、`ItemType` |

- 判定口径：**读者读到引用点就能往下找到定义**，不需要跳到其他章节。同一 `## APIs` 区块内，类型表连续排列在 Props 表之后即视为合规（不要求逐表紧贴某个 Props 表）。
- 同一类型被多处引用时只定义一次（放在首个引用章节的末尾），其余引用加锚点链接。
- ❌ 不把「只被 Methods 引用」的类型强行搬到 `## APIs`——它会与 Props 表隔开一整章，反而增加跳转成本。

### 2.1 标题 = 公开导出名

**标题必须是属性表里读者点击的那个名字**，即组件入口 `index.ts` 重命名后的公开导出名：

| 源码定义名 | 公开导出名 | 标题（✅） | 标题（❌ 旧写法） |
|:--|:--|:--|:--|
| `Item`（`Tabs.vue`） | `TabsItem` | `### TabsItem Type` | `### Item Type` |
| `Column` | `TableColumn` | `### TableColumn Type` | `### Column Type` |
| `Image`（`Image.vue`） | `ImageItem` | `### ImageItem Type` | `### Image Type` |
| `Option`（`Select.vue`） | `SelectOption` | `### SelectOption Type` | `### Option Type` |
| `Responsive`（`Avatar.vue`） | `AvatarResponsive` | `### AvatarResponsive Type` | `### Responsive Type` |

- 理由：旧规范「标题保留 SFC 内部名、锚点不随引用名变更」实测造成 **39/87（45%）标题与链接文字不一致**，且 `Item Type` / `Option Type` / `Image Type` 在多组件重复，目录树与页内查找无法定位。
- 代价与处置：标题改名 → 锚点 `#item-type` → `#tabsitem-type`，须**同文件内全量替换引用**；`B9e` 校验页内锚点可达性（实测全库改前 0 死链，改名后由脚本兜底）。
- ❌ **不用 `{#旧锚点}` 做兼容别名**：VitePress 一个标题只能有一个 id，`{#item-type}` 会覆盖自动锚点、使新锚点不存在，反而让新链接失效。要么一次改到位，要么不改。
- 文档自造类型（源码无对应导出，如 `Scrollbar` 的 `ScrollBehavior`、`ConfigProvider` 的 `Config`）沿用文档内命名，但同样加组件前缀，避免跨页重名。

### 2.2 三种形态与列数

| 形态 | 判定 | 列 | 示例 |
|:--|:--|:--|:--|
| **接口 / 对象结构** | 用户传入的配置对象，有多个字段、有可选项 | 4 列：名称 \| 说明 \| 类型 \| 默认值 | `TabsItem`、`TableColumn`、`MenuItemType` |
| **组件产出的回调 / 实例信息** | 字段全部由组件填写，用户只读 | 3 列：名称 \| 说明 \| 类型 | `SelectInfo`、`DateItem`、`DialogReactive` |
| **类型别名 / 联合 / 枚举** | 无字段，只有「名字 = 定义」一行 | 2 列：名称 \| 值 | `MenuKey`、`ItemType`、`ScrollBehavior` |

- ❌ 不给别名表硬套 4 列：会产生「说明」「默认值」两个恒空列，读者误以为漏填。
- 回调 / 实例类型用 3 列时，表前必须有一句明确引导：「以下字段均由组件产出，无需传入」——`默认值` 概念在此根本不成立（整列恒 `—` 属冗余）。
- 枚举值清单（无「名称」维度，如 `ScrollBehavior` 的三个可选值）用 2 列：`值 | 说明`。

### 2.3 首列 `?` 标记（与 Props 表相反）

- 4 列 / 3 列的接口表：**可选字段名前加 `?`**，必填字段不加。
- `?` 必须与源码 `interface` 的 `?` **逐字段一致**（`key` → `key`；`label?:` → `label?`）。
- 2 列的别名表：不加 `?`（表格只有一行，无"可选"概念）。
- 说明列不再重复写「可选 / 必填」（信息只写一次）。

### 2.4 行序

表格行序 **≡ 源码 `interface` 字段声明顺序**。语义相邻字段可微调，但禁止按字母序重排。

## 3. Slots / Methods / Events

| 表 | 列头 | 内容规范 |
|:--|:--|:--|
| `## Slots` | 名称 \| 说明 \| 用法 | 用法列写 `v-slot:default` / `v-slot:xxx` / `v-slot:xxx="{ a, b }"`；❌ 不写 `-` / `{ option: T }`（脚本 `B8` 拦截） |
| `## Methods` | 名称 \| 说明 \| 类型 | 类型列写**完整签名**：`(index: number) => boolean`、`() => void`；❌ 不写 `Function` / `(...args: any) => void` / 只写返回类型 |
| `## Events` | 名称 \| 说明 \| 类型 | 同上写完整回调签名 `(key: string \| number) => void`；`update:xxx` **不进本表**（由 Props 表的 `v-model` 标记表达） |

三张表列名**均不调整**：「类型」在 Props / Methods / Events 三处同词同义，改成「签名」「回调参数」只在局部制造新词，与全站一致性原则冲突。「用法」列已优于参考库的「参数」列，保持。

## 4. 工具函数文档（`docs/utils/functions/*.md`）

| 表 | 列头 | 说明 |
|:--|:--|:--|
| `## Params` | 名称 \| 说明 \| 类型 \| 默认值 | 首列统一「名称」，与组件 Props 表同口径（❌ 不写「参数」） |
| `## Return`（纯函数） | 类型 \| 说明 | 单返回值，**无名称维度**；❌ 不硬加「名称」列（只有一个返回值，名称列没有可写内容） |
| `## Return`（composable） | 名称 \| 说明 \| 类型 | 返回对象多字段，名称有真实信息（`match` / `start` / `stop` / `x`） |

- 判定：`add` / `formatNumber` / `debounce` 等纯函数用 **2 列**；`useXxx` 类 composable 用 **3 列**。
- 理由：这是「结构决定列数」原则的又一例——纯函数只返回一个值，没有「名称」维度可写；composable 返回对象，字段名是读者最需要的信息。两者按语义分流，不追求列数统一。

## 5. 其他表格

| 章节 | 列头 | 适用 |
|:--|:--|:--|
| `## CSS 变量` | 名称 \| 说明 \| 默认值 | 组件暴露的主题变量；名称列写 `--va-{组件}-xxx` 全名并加反引号。⚠️ 全站主清单 `docs/guide/parts/component-vars.md` 由 `scripts/gen-component-vars-doc.js` 生成，改表头必须改生成器后重新生成（❌ 禁手改生成物） |
| `## 自定义样式`（DOM 类名） | 名称 \| 说明 | 需列出内部类名时使用（首列写类名，列头仍用「名称」）；❌ 不混入「层级」「对应配置项」等自拟列。⚠️ 当前库内暂无此形态样本，新增时按本行执行 |
| format 占位符清单 | 标识 \| 示例 \| 描述 | 日期/时间格式化占位符（`YYYY` / `MM` / `DD`）；章节标题写 `### format 支持的格式化占位符列表` |
| 键盘操作 | 按键 \| 说明 | 组件有键盘交互时（`Dialog` / `Menu` / `Select`） |
| 离散 API 调用方式 | 调用方式 \| API \| 适用位置 | `createDiscreteApi` 类组件（`message` / `modal` / `notification`） |

> ⚠️ 上表的「format 占位符 / 键盘操作 / 离散 API」三类是**无「名称」维度的专用表**（首列分别是占位符、按键、调用方式），属 §0「首列=名称」规则的**显式例外**；除这三类外，任何表首列都必须叫「名称」。

## 6. 书写格式（确定性规则）

1. **带首尾管道**：`| 名称 | 说明 | 类型 | 默认值 |`，分隔行 `| :-- | :-- | :-- | :-- |`。
   - ⚠️ 修订项目旧规范（原要求"无首尾竖线的紧凑写法"）：实测 193 张带管道 / 153 张紧凑，两种渲染一致，但带管道在增删列时更不易错位。**新写与改动的表按带管道格式；存量不追溯。**
2. **表头不得截断**：`默认值` 不写成 `默认`，`名称` 不写成 `参数`（`B9` 拦截）。
3. **单元格内禁裸对象字面量**：`{ label: 'label' }` 会被 md 当作上一个标签的 HTML 属性（轻则内容丢失，重则 `docs:build` 报 `Duplicate attribute`），一律用反引号包裹。
4. **联合类型统一 `&#124;`**；单个 `|` 不要裸写。
5. **单元格内多个要点用 `<li>` 列表**（与现有 `filterOption` 等长说明一致），不用 `<br>` 堆叠。
6. **表格只承载结构化对照**：需要展开解释（多段落、代码块、参数传递链路）时，表格上方补一句引导 + 表格下方用正文展开，禁止把整段说明塞进「说明」列。

## 7. 自检（脚本 `B9` + 手工 grep）

| 检查 | 判定口径 | 命中处置 |
|:--|:--|:--|
| B9a 首列列名 | 表格首列单元格内容为「参数」 | FAIL（应为「名称」） |
| B9b 表头截断 | 表头末列单元格内容为「默认」 | FAIL（应为「默认值」） |
| B9c 类型标题 = 链接文字 | 提取 `### Xxx Type` 与指向 `#xxx-type` 的链接文本比对 | 不一致 → WARN（迁移期） |
| B9d 组件标题带 Props | `## APIs` 区块内出现纯英文 `### Xxx` | WARN（应为 `### Xxx Props`） |
| B9e 页内锚点可达 | 任意纯 ASCII 页内锚点 `(#slug)` 无对应标题：`#xxx-type` 额外要求链接文字 = 标题名；`#xxx-props` 等改名后的锚点只判可达性 | FAIL（标题改名未同步链接） |
| B9f 必填双标记 | Props 表默认值列为 `—` 但名称列无 `required` 标签 | WARN（补 `<Tag color="red">required</Tag>`） |
| B9g CSS 变量表首列 | `## CSS 变量` 区块表头首列为「变量」 | WARN（应为「名称」） |
| B9h 工具函数 Params 首列 | `docs/utils/functions/*.md` 表格首列为「参数」 | FAIL |

> 首列 / 末列的单元格判定由脚本 `awk` 按 `&#124;` 分隔实现（兼容带首尾管道与紧凑两种历史写法），无需手工 grep。

## 8. 迁移口径（存量文档）

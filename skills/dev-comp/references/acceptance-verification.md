# 验收提示规范（演示页目测验收）

> 本文件是「演示用例验收提示」的**单一权威规范源**。阶段 3（生成）/ 阶段 5（清除）/ 脚本 C6 校验按需加载。
> 背景：此前 Gate 3 / Gate 5 的人工验收只有「浏览器实测」一句话，验收点散落在 AI 的临时判断里——用户拿到演示页后不知道点哪里、看什么，验收退化为「看起来没报错」。本规范把验收点固化成**页面上可见、可判定、可脚本清除**的提示块。

---

## 0. 定位与边界

| 维度 | 说明 |
|:--|:--|
| 是什么 | 演示页中每个用例附带的「操作 + 观察」说明块，供人工目测验收 |
| 不是什么 | ❌ 不是用例简介描述（那个会同步进 docs 并永久保留）；❌ 不是 `<!-- -->` 注释（页面上看不见，等于没写） |
| 生命周期 | 阶段 3 生成 → 保留至阶段 5 人工验收完成 → **阶段 5 清除，0 残留**（脚本 C6 FAIL 级） |
| docs 同步 | ❌ **不同步 docs**（docs 只收简介描述）；G4 用例对齐忽略该区块 |

---

## 1. 标记规范（强约束 · 脚本按字面量匹配）

开始标记（逐字固定）：

```
<!-- 验收提示（阶段 5 清除） -->
```

结束标记（逐字固定）：

```
<!-- /验收提示 -->
```

- 每个用例**一个**提示块，块内根元素 `<div class="demo-acceptance">`
- 提示样式集中为**一个** `<style lang="less" scoped>` 块，整体同样被两个标记包裹，且只放 `.demo-acceptance*` 规则
- ❌ 不改写标记文本、不加序号/空格/换行变体（脚本与清除命令按字面量执行）
- ❌ 不把验收提示写进 `::: details`、不写进 docs、不写进组件源码

---

## 2. 内容要求

| 项 | 要求 |
|:--|:--|
| 必备维度 | 必须同时有「操作」与「观察」两个维度；无需操作的用例写「无需操作」+ 触发条件（如「挂载后自动开始」） |
| **可判定** | 每条观察点必须能回答「对 / 不对」。❌ 禁止「显示正常」「样式没问题」这类无法证伪的表述 |
| **可控时长** | 涉及计时的用例必须给出**能被目测完整看完**的时长（≤ 15 秒）；❌ 用 1 年 / 24 小时这类无法验收的初值充当「到期」用例 |
| **控制台** | 涉及事件 / 告警的用例，必须写明预期输出的**逐字文本**与次数 |
| **主题** | 涉及颜色的用例，写「切换右上角主题为暗色后再次观察」并列明预期变化 |
| **易误判项** | 天然会被当成 bug 的正常行为必须显式解释（如向上取整导致 `24:00:00:999`、多实例毫秒天然不同步、后台切回后补发事件），写明「属正常现象，不是缺陷」 |
| 布局 | 涉及排版的用例写明对齐方式、间距、等宽 / 并排关系 |

### 2.1 信息增量自检（与简介描述同款判据）

写「观察」前逐条过一遍：

- 能否只看标题 + 示例就得到该结论？能 → 该条是噪音，删
- 该条是否只是「复述代码里写的属性值」？是 → 改为**可观察的后果**（写「数值每秒变化一次」，不写「`interval` 为 1000」）
- 该条是否与同区块其它条目重复？重复 → 合并

## 3. 生成要点（阶段 3）

1. **覆盖**：演示页每个 `<h2 class="mt30 mb10">` 用例各一块，数量一致（脚本 C6 WARN 兜底）
2. **验收盲区自检**（下笔前先答，答不出就补用例）：
   - 本次改动的**核心行为**里，哪一条在现有用例下用户**看不到**？→ 补可控时长的用例（典型：`finish` 事件、到期文案切换、暂停恢复、重置）
   - 本次**新增的 API 形态**是否在演示页有对应示例？→ 没有则补（典型：同名「属性 + 插槽」双形态只演示了插槽）
   - 有没有「只演示了理想路径」而遗漏终态 / 空态 / 极值？→ 补
3. **顺序**：验收提示紧跟用例的简介描述之后、示例容器之前
4. **与简介描述不混写**：简介描述是给用户的用法说明（进 docs），验收提示是给验收者的操作清单（不进 docs）——两处都写会让用户读到重复内容

---

## 4. 清除流程（阶段 5 第 5 步 · 必做）

```bash
# 删除全部「验收提示」区块（含标记行与样式块）
perl -0777 -pi -e 's/[ \t]*<!-- 验收提示（阶段 5 清除） -->.*?<!-- \/验收提示 -->\n?//gs' src/views/{组件名}/Index.vue

# 验证：两个 grep 都必须为 0
grep -c "验收提示" src/views/{组件名}/Index.vue
grep -c "demo-acceptance" src/views/{组件名}/Index.vue
```

- 清除后演示页应回到「标题 → 可选描述 → 示例容器」的纯结构
- 若删除后残留空行，随阶段 5 精修一并清理（`refine-spec.md` §2.4 空行口径）
- 清除属实质改动 → **必须复验**（lint + type-check + 浏览器实测 + `pnpm test`）

## 5. 脚本校验（`scripts/validate-component.sh` C6）

| 检查 | 判定 | 级别 |
|:--|:--|:--|
| 标记注释残留 | 演示页出现 `验收提示（阶段 5 清除）` → FAIL | FAIL（阻断 Gate 5） |
| 提示块残留 | 出现 `.demo-acceptance` → FAIL | FAIL |
| 覆盖完整性 | `<h2>` 用例数 ≠ 提示块数 → WARN | WARN（阶段 3/4 期间出现未写全的提示时提示） |

> 阶段 3/4 期间提前跑脚本看到 C6 FAIL 属预期（尚未到清除步骤）；**Gate 5 必须为 PASS**。

## 反模式清单

| 反模式 | 正确做法 |
|:--|:--|
| 验收提示写成简介描述（进 docs、被用户当用法读） | 两者分离：描述进 docs，提示只在演示页且阶段 5 删除 |
| 用 `<!-- -->` 注释写验收点 | 页面上看不见，等于没写；必须渲染为可见元素 |
| 只写「观察」不写「操作」 | 验收者不知道要触发什么，事件类用例永远验不到 |
| 用「显示正常」当观察点 | 写可判定的具体结果（文本 / 次数 / 颜色 / 间距 / 控制台输出） |
| 到期类用例仍用 1 年 / 24 小时初值 | 补 ≤15 秒的短倒计时用例，让 `finish` 可被目测 |
| 标记文本随手改写（加序号、换括号） | 逐字固定，脚本与清除命令按字面量执行 |
| 清除时手动逐块删、删漏一处 | 用 §4 的 perl 命令 + 两次 grep 归零 |

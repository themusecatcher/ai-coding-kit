# steps/ 步骤规范目录

> 本目录包含 dev-flow 开发流程中每个步骤的详细规范文件。
> 采用 Prompt Chaining 架构，每个步骤按需加载，禁止一次性加载多个。

## 加载协议

1. 流程启动后先加载 `step-router.md`（步骤路由器，唯一导航权威）
2. 每个步骤开始时：`read_file("steps/step-N-xxx.md")` 加载该步骤规范
3. 每个步骤完成后：输出结构化完成标记 JSON → 门控验证 → 才能加载下一步
4. ❌ 禁止一次性加载多个步骤文件
5. ❌ 禁止未加载步骤文件就执行该步骤

## 执行深度与步骤关系

```text
所有需求 → 阶段0 → 步骤1 → 2 → 3 → 4（智能评估推荐执行深度）→ 4.5 → 5 → 5.5 → 6
↓
┌─── 标准执行 → 步骤7（完整） → 结束
└─── 完整执行 → 步骤7（裁剪） → 8 → 9 → 10 → 结束
├─── 批次执行 → 步骤7（精简版） → 切换下一批次 → 4.5 → 5 → 5.5 → 6 → 7 → ... → 最后一批 → 步骤7（完整） → 结束

```

- **标准执行**：步骤7 执行全部环节（清理+L2审查+Commit+Devlog+Knowledge+反思），流程结束
- **完整执行**：步骤7 仅执行清理+L2审查，Commit/Devlog/反思推迟到步骤10
- **批次执行**：步骤7 执行精简版（清理+L2审查+Commit[batch N/M]+增量devlog），然后切换下一批次从步骤4.5开始循环，最后一批自动切换为标准/完整执行

## 分级钩子（Tiered Hooks）

每个步骤完成后的钩子重量不同，减少轻量步骤的 Token 开销：

| 级别 | 步骤 | 说明 |
| --- | --- | --- |
| 🔴 重量级 | 4、5、6、7 | 完整 outputs + 状态快照 + 逐项门控校验 |
| 🟡 中量级 | 3、5.5、8 | 精简 outputs + 仅校验关键字段 |
| 🟢 轻量级 | 1、2、4.5、9、10 | 最小 outputs + 仅校验 status + next_step |

## 回退路径速查

| 当前步骤 | 触发条件 | 回退到 |
| --- | --- | --- |
| 步骤4 | 换方案 | 步骤3 |
| 步骤5 | 计划无法执行 | 步骤4 |

> 完整回退对照表 → `references/rollback.md`

## 文件命名规则

- 格式：`step-{N}-{英文名}.md`，N 为步骤编号（支持小数如 4.5、5.5）
- `step-router.md` 是特殊文件，不对应具体步骤，而是步骤间的导航路由器
- `step-8-10-full.md` 包含步骤 8~10 的完整规范，仅完整执行时按需加载

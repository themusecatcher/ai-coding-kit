# Figma 设计稿处理流程（三模式通用）

当用户提供 Figma 设计稿链接时（无论处于完整执行、标准执行还是迭代修复场景），统一按以下两级策略处理：

| 级别 | 操作 | 判断标准 |
| --- | --- | --- |
| **① MCP 获取** | 调用 `get_figma_data(fileKey, nodeId)` 获取结构化设计数据 | 成功获取且信息详细（包含完整的文本内容、布局层级、组件属性等），比截图能提供更多细节 → **直接使用** |
| **② 请用户截图** | 请用户在对话中直接发送设计图截图 | MCP 调用失败（限流/超时/网络错误）、或返回数据不够详细（缺失关键文本/布局信息模糊/组件层级不完整）→ **降级到截图** |

**判断原则**：对话中截图由 AI 视觉模型直接理解，能同时捕获文字、布局、交互状态、颜色等全维度信息，信息完整度通常优于 MCP 结构化数据。因此只有当 MCP 返回的数据**确实比截图更详细**时才使用 MCP 数据，否则一律请用户提供截图。

**降级话术模板**：「Figma 数据获取不够详细，请直接在对话中发送设计图截图，我通过截图来理解设计细节。」

**迭代修复场景**：如果用户在迭代修复时提供了新的 Figma 链接（如设计稿有更新），仍按上述两级策略处理，不因"已有 Figma 信息"而跳过。

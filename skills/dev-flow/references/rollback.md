> 本文件按需加载，不随 flow.md 一起加载。

| 当前步骤 | 问题 | 回退到 |
| --- | --- | --- |
| 步骤 4 | 用户选择「修改」 | 步骤 4（更新计划后重新弹出选项） |
| 步骤 4 | 用户选择「换方案」 | 步骤 3 |
| 步骤 4 | 用户选择「暂存」 | 锁定计划 → 写入工作上下文 → 结束当前会话 |
| 步骤 4 | 用户选择「取消」 | 终止 |
| 步骤 5 | 部分执行完成，用户说"继续执行" | 步骤 5（恢复剩余步骤） |
| 步骤 5 | 计划无法执行 | 步骤 4（暂停，说明原因，重新汇报） |
| 步骤 5 | 范围遗漏 | 步骤 4（补充计划后重新确认） |
| 步骤 5.5a | 🔴 必须修复项 | 就地修复 → 重新审查该文件 |
| 步骤 5.5c | Lint/编译错误 | 直接修复 → 回 5.5a 审查修复代码 |
| 步骤 6A V1/V2/V3 | 编译/类型/Lint 错误 | 直接修复 → 即时验证 → 回 5.5a 审查修复代码 |
| 步骤 6A V4 | Browser 验证失败 | 分析原因 → 回步骤 5 修复 → 重走 5.5（审查+自检）→ 6A |
| 步骤 6A V5 | 测试失败 | 分析原因 → 回步骤 3 重新制定方案 → 4 → 5 → 5.5 → 6A |
| 步骤 6A V6 | 安全问题 | 直接修复 → 即时验证 → 回 5.5a 审查修复代码 |
| 步骤 6A V7 | 预期外变更 | 清理 → 即时验证 → 回 5.5a 审查 |
| 步骤 6B | 用户跳过验收 | 进入 6C 联调判断（或直接步骤 7） |
| 步骤 6B | 部分问题 | 清理调试代码 → 步骤 5（修复后重新走 5.5 → 6A → 6B） |
| 步骤 6B | 验收不通过 | 清理调试代码 → 步骤 3（重新制定方案） |
| 步骤 6C | 用户跳过联调 | 清理调试代码 → 直接进入步骤 7 |
| 步骤 6C | 后端未就绪 | 暂存前置处理（清理/Commit 可选）→ 暂存等联调 → 更新工作上下文 → 等待恢复信号 |
| 步骤 6C | 前端问题 | 回退步骤 5 修复 → 5.5 → 6A → 继续 6C |
| 步骤 6C | 后端问题 | 记录问题 → 暂存等后端修复 → 恢复后继续 6C |
| 步骤 6C | 协议不一致 | 前后端协商 → 可能回退步骤 3 重新制定方案 |
| 步骤 6C | 联调通过 | 清理调试代码 → 步骤 7 |
| 步骤 7 | 清理调试代码后编译异常 | 即时验证 → 回 5.5c 自检 → 修复 → 回 5.5a 审查 |
| 步骤 7 | L2 审查 🔴 修复后 | 即时验证 → 回 5.5a 审查修复代码 → 5.5c 自检 → 重新 L2 |
| 步骤 6→7 之间 | 用户验收/实际测试中发现新问题 | 修复 → 重走 5.5 → 6 → 7（完整链路，步骤 7 必须完整执行 A~J 环节） |

## 批次执行回退机制

> 批次模式下的回退规则。批次内部回退不影响其他批次，跨批次回退需重新评估批次规划。

| 当前步骤 | 问题 | 回退到 |
| --- | --- | --- |
| 步骤 4 | 用户选择「分批执行」后要求调整批次划分 | 步骤 4（更新批次规划后重新弹出选项） |
| Batch N 步骤 5 | 当前批次计划无法执行 | 步骤 4（暂停当前批次，说明原因，重新评估批次规划） |
| Batch N 步骤 5 | 发现需要修改已完成批次的代码 | 记录为跨批次依赖问题 → 在当前批次中修复 → 更新已完成批次的 devlog |
| Batch N 步骤 6 | 验证失败，根因在已完成批次 | 在当前批次中修复 → 重走 5.5 → 6A（不回退已完成批次） |
| Batch N 步骤 6 | 验证失败，需要重新制定方案 | 回退步骤 3 → 重新评估是否仍需分批 + 重新规划批次 |
| Batch N 步骤 7 | 批次 commit 后发现问题 | 在下一批次中修复（原子提交原则，不修改已提交的批次） |
| 批次切换 | 用户要求跳过某个批次 | 标记该批次为 skipped → 继续下一批次 → 最后一批时评估是否需要补回 |
| 批次切换 | 用户要求重做某个已完成批次 | 回退该批次状态为 in_progress → 重新执行 4.5→5→5.5→6→7 |

## 回退触发的交互式选项汇总

> 本章节抽取各步骤"发现问题 → 弹选项让用户决策"的通用交互式选项模板，供各步骤 cross-ref。
> 所有选项必须遵循 `~/.codebuddy/rules/AI行为规范.mdc` §「交互式选项一致性规则」的双重展示要求（文本表格 + `ask_followup_question`）。
> ⚠️ **重要**：以下模板是**通用参考范本**，各步骤的实际选项**可按场景裁剪**（增删选项、调整文案），但必须满足：
>
> 1. 保留至少 2 个合理选项（不能只给一个选项）
> 2. 选项覆盖主要决策路径（继续 / 回退 / 终止 三类中至少两类）
> 3. 裁剪后仍符合「交互式选项一致性规则」的双重展示要求

### 通用模板 A：验证失败 / 执行受阻（3 次熔断、计划无法执行等）

| 选项 | 说明 |
| --- | --- |
| 🔄 回退重做 | 回到步骤 {N} 重新执行（N 按上方回退对照表确定） |
| 🛠️ 我来处理 | 暂停流程，由我手动处理后告知你继续 |
| ⏭️ 跳过此阶段 | 忽略该阶段（仅非关键阶段允许，熔断时谨慎使用） |
| ❌ 终止 | 终止本次任务 |

**适用场景**：step-5 计划无法执行、step-6A 3 次失败熔断、step-6C 前后端问题。

### 通用模板 B：质量审查 🟡 建议修复项

| 选项 | 说明 |
| --- | --- |
| 🔧 全部修复 | 修复所有 🟡 建议项 |
| ⏭️ 全部跳过 | 跳过所有 🟡 建议项 |
| ✏️ 部分修复 | 告诉我要修复哪几项（如 "修 1,3"） |

**适用场景**：step-5.5a L1 审查、步骤 7 环节 G L2 审查。

### 通用模板 C：清理/回退类

| 选项 | 说明 |
| --- | --- |
| 🧹 全部回退/清理 | 对所有预期外文件/遗留调试代码执行处理 |
| ✏️ 部分回退/清理 | 告诉我保留哪几项 |
| ⏭️ 保留全部 / 跳过 | 不做处理，继续下一步 |

**适用场景**：步骤 7 环节 A 预期外变更、步骤 7 环节 B 调试代码清理。

### 通用模板 D：步骤流转推进选项（每步骤完成后）

| 选项 | 说明 |
| --- | --- |
| ▶️ 继续步骤 {N+1}（{步骤名}） | 门控已通过，进入下一步 |
| ⏸️ 暂停，我有补充/疑问 | 暂停等待用户输入 |
| 🔁 回退步骤 {N} 重新执行 | 本步骤有遗漏，重做 |

**适用场景**：所有步骤完成后（精简模式豁免见 `steps/step-router.md` §步骤流转交互规则）。

### 通用模板 E：暂存/取消终态

| 选项 | 说明 |
| --- | --- |
| ⏸️ 暂存 | 锁定当前进度，写入工作上下文，结束当前会话 |
| ❌ 取消 | 终止本次任务，不保留进度 |

**适用场景**：step-4 用户决策、需要用户中断的任何场景。
